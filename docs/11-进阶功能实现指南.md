### 功能 1：发票导出 CSV ✅ 已完成

**目标**：发票列表页加"导出"按钮，点击下载所有发票为 CSV 文件。

**学到什么**：

**涉及的文件**：
| 操作 | 文件 |
|------|------|
| 已新建 | `app/api/invoices/csv/route.ts`（API 路由） |
| 已改 | `app/dashboard/invoices/page.tsx`（加导出按钮） |

**关键代码骨架**：

```ts
// app/api/invoices/csv/route.ts
import { prisma } from '@/app/lib/prisma';

export async function GET() {
  // 1. 查所有发票（带客户信息）
  const invoices = await prisma.invoice.findMany({
    include: { customer: true },
    orderBy: { date: 'desc' },
  });

  // 2. 拼成 CSV 字符串
  const header = '客户名称,邮箱,金额(分),状态,日期\n';
  const rows = invoices.map(inv =>
    `${inv.customer.name},${inv.customer.email},${inv.amount},${inv.status},${inv.date.toISOString().split('T')[0]}`
  ).join('\n');
  const csv = header + rows;

  // 3. 返回 CSV 文件（设置响应头让浏览器下载）
  return new Response(csv, {
    headers: {
      'Content-Type': 'text/csv; charset=utf-8',
      'Content-Disposition': 'attachment; filename="invoices.csv"',
    },
  });
}
```

页面里加按钮：
```tsx
// app/dashboard/invoices/page.tsx 里加
<a href="/api/invoices/csv">导出 CSV</a>
// 注意：用 <a> 不用 <Link>，因为这是下载文件不是页面跳转
```

### 功能 3：表单输入数据保留

**目标**：创建客户校验失败后，输入框保留用户之前填的数据，不消失。

**学到什么**：Server Action 返回值设计、非受控组件回填

**涉及的文件**：
| 操作 | 文件 |
|------|------|
| 改 | `app/lib/actions/customer.ts`（createCustomer 校验失败时多返回原始数据） |
| 改 | `app/ui/customers/create-form.tsx`（用 defaultValue 回填） |
| 改 | `app/lib/actions/invoice.ts`（createInvoice 也改，保持一致） |
| 改 | `app/ui/invoices/create-form.tsx`（同样回填） |

**关键代码骨架**：

**注意**：defaultValue 只在元素首次挂载时生效，之后的 re-render 不会更新。
要让回填生效，有两种方式：

**方式 A：改成受控组件（推荐，和 Vue 的 v-model 类似）**

```tsx
// create-form.tsx —— 用 useState 管理输入值
'use client';
import { useState } from 'react';

export default function CreateCustomerForm() {
  const [name, setName] = useState('');
  const [email, setEmail] = useState('');
  const [state, dispatch] = useActionState(createCustomer, initialState);

  return (
    <form action={dispatch}>
      <input
        name="name"
        value={name}
        onChange={(e) => setName(e.target.value)}
      />
      <input
        name="email"
        value={email}
        onChange={(e) => setEmail(e.target.value)}
      />
    </form>
  );
}
// 校验失败后 name/email 还在 state 里，输入框自然保留 ✅
```

**方式 B：Server Action 返回原始数据 + input 加 key 强制重建**

```ts
// customer-action.ts —— 校验失败时返回 rawInput
if (!validatedFields.success) {
  return {
    errors: validatedFields.error.flatten().fieldErrors,
    message: '有字段未填写或格式不正确，创建客户失败。',
    rawInput: {
      name: formData.get('name') as string,
      email: formData.get('email') as string,
    },
  };
}
```

```tsx
// create-form.tsx —— key 变化时 React 销毁重建 input，defaultValue 重新生效
<input
  key={state.rawInput ? 'filled' : 'empty'}
  defaultValue={state.rawInput?.name || ''}
/>
```

> 方式 B 有副作用（重建会丢失焦点等状态），所以推荐方式 A。

**参考现成模块**：无（这是对现有表单的改进）

### 功能 4：数据统计图表（客户消费排行榜）✅ 已完成

**目标**：仪表盘加一个"客户消费排行榜"柱状图，显示每个客户的总消费金额。

**学到什么**：
- Prisma 聚合查询（groupBy / aggregate）
- 数据可视化（复用现有 revenue-chart 的样式）

**涉及的文件**：
| 操作 | 文件 |
|------|------|
| 已新建 | `app/lib/data/dashboard.ts` 里的 `fetchTopCustomers`（聚合查询） |
| 已新建 | `app/ui/dashboard/top-customers.tsx`（图表组件） |
| 待改 | `app/dashboard/(overview)/page.tsx`（加这个图表到首页） |

**关键代码骨架**：

```ts
// 查每个客户的总消费金额（已支付），按金额倒序取前 5
async function fetchTopCustomers() {
  const result = await prisma.invoice.groupBy({
    by: ['customer_id'],
    where: { status: 'paid' },
    _sum: { amount: true },
    orderBy: { _sum: { amount: 'desc' } },
    take: 5,
  });

  // 再查出这些客户的 name（groupBy 只返回 id，要单独查 name）
  const customers = await prisma.customer.findMany({
    where: { id: { in: result.map(r => r.customer_id) } },
    select: { id: true, name: true },
  });

  // 拼在一起
  return result.map(r => ({
    name: customers.find(c => c.id === r.customer_id)?.name || '未知',
    total: r._sum.amount || 0,
  }));
}
```

**关键概念——groupBy**：
- 类比 SQL 的 `GROUP BY customer_id`
- `by: ['customer_id']` → 按客户分组
- `_sum: { amount: true }` → 每组求 amount 的和
- `orderBy: { _sum: { amount: 'desc' } }` → 按求和结果倒序

export async function batchUpdateStatus(formData: FormData) {

**目标**：现在只有 seed 的一个账号能登录。加一个注册页面，用户能自己注册账号。

**学到什么**：

**涉及的文件**：
| 操作 | 文件 |
|------|------|
| 新建 | `app/lib/actions/user.ts`（register Server Action） |
| 新建 | `app/ui/register-form.tsx`（注册表单） |
| 新建 | `app/register/page.tsx`（注册页面） |
| 改 | `app/page.tsx`（落地页加注册入口） |

**关键代码骨架**：

```ts
// app/lib/actions/user.ts
"use server";
import { z } from 'zod';
import bcrypt from 'bcrypt';
import { redirect } from 'next/navigation';
import { prisma } from '@/app/lib/prisma';

const RegisterSchema = z.object({
  name: z.string().min(2, { message: '至少 2 个字符' }),
  email: z.string().email({ message: '邮箱格式不正确' }),
  password: z.string().min(6, { message: '密码至少 6 位' }),
});

export async function register(prevState: any, formData: FormData) {
  // 1. Zod 校验
  const validatedFields = RegisterSchema.safeParse({
    name: formData.get('name'),
    email: formData.get('email'),
    password: formData.get('password'),
  });
  if (!validatedFields.success) {
    return { errors: validatedFields.error.flatten().fieldErrors };
  }

  const { name, email, password } = validatedFields.data;

  // 2. 检查邮箱是否已注册（email 是 @unique）
  const existing = await prisma.user.findUnique({ where: { email } });
  if (existing) {
    return { message: '该邮箱已注册' };
  }

  // 3. 密码哈希 + 写库
  const hashedPassword = await bcrypt.hash(password, 10);
  await prisma.user.create({
    data: { name, email, password: hashedPassword },
  });

  // 4. 跳转到登录页
  redirect('/login');
}
```

注册表单参考 `app/ui/customers/create-form.tsx` 的结构，绑定 `register` action。

### 功能 7：权限系统（RBAC）

**目标**：加"管理员"和"普通用户"两种角色，普通用户只能看自己的发票，管理员能看所有。

**学到什么**：
- 数据库迁移（改 schema → db push → generate）
- NextAuth 的 session 里带自定义字段
- middleware 按角色拦截路由

**涉及的文件**：
| 操作 | 文件 |
|------|------|
| 改 | `prisma/schema.prisma`（User 加 role 字段） |
| 改 | `auth.ts` + `auth.config.ts`（session 带 role） |
| 改 | `app/lib/data/` 下的查询函数（按用户过滤） |
| 改 | `middleware.ts`（按角色拦截） |

**关键步骤**：

第 1 步：数据库加 role 字段
```prisma
// schema.prisma
model User {
  id       String @id
  name     String
  email    String @unique
  password String
  role     String @default("user")   // ← 新增，默认普通用户
}
```
然后跑 `npx prisma db push` + `npx prisma generate`

第 2 步：NextAuth session 带 role
```ts
// auth.ts 的 callbacks 里加
callbacks: {
  async jwt({ token, user }) {
    if (user) token.role = user.role;   // 登录时把 role 存进 token
    return token;
  },
  async session({ session, token }) {
    if (session.user) session.user.role = token.role;  // session 里也能拿到 role
    return session;
  },
},
```

第 3 步：查询时按用户过滤
```ts
// data.ts 的查询函数加 where 条件
const invoices = await prisma.invoice.findMany({
  where: session.user.role === 'admin' ? {} : { customer_id: session.user.id },
  // 管理员看全部，普通用户只看自己的
});
```

第 4 步：middleware 拦截
```ts
// auth.config.ts 的 authorized 里加角色判断
if (pathname.startsWith('/dashboard/admin') && user.role !== 'admin') {
  return false;  // 普通用户访问管理员页面被拦
}
```

**关键概念**：
- 数据库迁移：schema 改了 → db push 同步数据库 → generate 更新类型
- session：登录后存在 cookie 里的"身份证明"，可以带自定义字段

**参考现成模块**：`auth.ts` + `auth.config.ts` + `middleware.ts`

### 功能 9：实时通知（仪表盘数字自动刷新）

**目标**：创建发票后，仪表盘首页的数字实时更新，不用手动刷新。

**学到什么**：

- 或者 Server-Sent Events

**涉及的文件**：
| 操作 | 文件 |
|------|------|
| 新建 | `app/api/stats/route.ts`（返回统计数据的 API） |
| 改 | `app/ui/dashboard/cards.tsx`（改用客户端轮询） |

**关键代码骨架**（轮询方式，最简单）：

```ts
// app/api/stats/route.ts
import { prisma } from '@/app/lib/prisma';

export async function GET() {
  const [invoiceCount, customerCount] = await Promise.all([
    prisma.invoice.count(),
    prisma.customer.count(),
  ]);
  return Response.json({ invoiceCount, customerCount });
}
```

```tsx
// cards.tsx 改为客户端组件，每 30 秒轮询一次
'use client';
import { useEffect, useState } from 'react';

export function CardWrapper() {
  const [stats, setStats] = useState(null);

  useEffect(() => {
    const fetchStats = async () => {
      const res = await fetch('/api/stats');
      setStats(await res.json());
    };
    fetchStats();
    const timer = setInterval(fetchStats, 30000); // 每 30 秒
    return () => clearInterval(timer);
  }, []);

  if (!stats) return <div>加载中...</div>;
  return <Card title="总发票数" value={stats.invoiceCount} />;
}
```

**关键概念——轮询 vs SSE**：
- 轮询：客户端每隔 N 秒主动请求一次（简单，但有延迟）
- Server-Sent Events：服务器有新数据时主动推（实时，但实现复杂）

**参考现成模块**：`app/ui/dashboard/cards.tsx`（现在是服务端组件，改成客户端组件）
